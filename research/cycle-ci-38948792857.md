# Improvement Cycle — CI fix documents.py regressions

## Problem
GitHub CI run 38948792857 (commit 4e8e216) failed on unit tests for both Python 3.11 and 3.12.
Local smoke was 100%, but `tests/unit` document tests regressed after the BM25L + section-chunking edit in documents.py.

## Research
- CI unit step runs `pytest tests/unit`. Failures were in digit ranking, embed persist, IDF coverage, and span-cite extraction — not coding/search routing.
- Numeric tokens were dropped by `[a-zA-Z']+`, so "March 12" could not outrank "March 12ish".
- `search()` omitted the `overlap` key required by ranking tests.
- `query_aware_extract` lacked cover-span tie-break, so equal-overlap sentences preferred the earlier wide span.
- Embed cache was warmed on open and blobs were float32, so reload exact-match and empty-cache asserts failed; missing blobs were not backfilled.

## Implementation
- content_tokens / search / BM25 collection tokens include digits.
- search result includes `overlap`; exact digit match gets a small bonus.
- query_aware_extract ranks by overlap, pair hits, tighter min_cover_span, then earlier sentence.
- Added `_load_embed` / `_persist_embed` / `_decode_embed`. Store float64 for exact reload. Lazy cache (empty on reopen). Search backfills missing embeddings.
